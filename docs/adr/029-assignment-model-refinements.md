# ADR-029: Уточнения модели «Роли и Функции» перед новым экспериментом

## Статус

Принято; **уточняет и дополняет** [ADR-028](028-roles-functions-model-and-assignment.md) (не заменяет его). Правки внесены в [`docs/assignment/`](../assignment/MODEL.md) (MODEL, MESSAGE, COORDINATOR) 2026-07-28. Инструкции ролей эксперимента этим ADR **не меняются**.

## Дата

2026-07-28

## Контекст

Перед запуском нового эксперимента экспериментатор заострил ряд моментов модели и проверил их на противоречия с уже записанным в `docs/assignment/`. Прямых противоречий-блокеров не выявлено; часть формулировок в контрактах была размытой и уточнена. Открытые вопросы сознательно **не решаются здесь** — они уходят входными данными в новый эксперимент.

## Решение

### 1. Кардинальность входа и выхода Исполнителя

- На входе Исполнителя — **ровно одно** Поручение. Следующее ждёт, пока до него дойдёт **очередь Координатора**.
- На выходе — **ноль или несколько** Поручений другим Исполнителям.
- Нет валидного Поручения на входе → Исполнитель **отказывается работать** и эскалирует Пользователю.

### 2. Fan-in не вводим; «Происхождение» — список предков

- Несколько входных Поручений «в параллель» **не** вводятся (сложно для понимания, контроля и реализации Координатора; один-в-один упрощает всё).
- Поле **«Происхождение»** — список **всех** Поручений-предков (денормализация ради поиска и контроля; избыточно к графу реестра). Номер из «В ответ на» входит в этот список.

### 3. Состояние Исполнителя = рабочая директория Поручения

- Состояние существует **только в рамках конкретного Поручения** и материализуется как его **рабочая директория**. Вне Поручения Исполнитель состояния не хранит.
- Рабочая директория — **устойчивый источник истины** (переживает выключение); контекст LLM субагента эфемерен. Это решает открытый вопрос «что станет с контекстом до/после выключения».
- При возобновлении Исполнитель **перевходит в рабочую директорию своего исходного Поручения**, куда доставлен ответ.
- Инвариант самодостаточности теперь читается как «текст Поручения **+ его рабочая директория**».

### 4. PRD и Поручение — разные артефакты

- **PRD** — **входной** документ и источник смысла: узнаваемый формат, понятный внешнему Пользователю и его ИИ-ассистенту.
- Внутри пайплайна PRD не используется; для передачи смысла введён отдельный вид документа — **Поручение**. Часть структуры PRD **позаимствована** для тела Поручения.
- Из входного PRD Координатор создаёт **Поручение №1**.

### 5. Вход и остановки Координатора

- Вход — **любая информация**; в первый раз **обязателен PRD**.
- Обработка **по одному** необработанному Поручению: найти → выбрать Исполнителя → запустить.
- **Периодический HITL:** после N запущенных Поручений (например, **10**) **или** при отсутствии необработанных Поручений — стоп для человека.
- Перед остановкой Координатор **выдаёт статус**.
- Введена ветка **возобновления Поручения со статусом ЭСКАЛАЦИЯ** (приём информации от Пользователя, проверка выполнения) — с открытыми вопросами.

### 6. Термины Skill / Agent / Command

Cursor-специфику (конкретные пути) **не фиксируем**. Термины **Skill** (приём/передача Поручения — общий модуль), **Agent** (Исполнитель), **Command** (Координатор — точка входа) используются как **нейтральные ярлыки** уровня инструмента.

## Обоснование

- «Ровно одно на входе» + очередь = простая, наблюдаемая и завершаемая семантика Координатора; убирает сложность параллельного fan-in.
- Рабочая директория как единственная область состояния делает процесс **устойчивым к перезапуску** и снимает противоречие между «субагент с чистого листа» и опорой на эфемерный `resume`.
- Разведение PRD и Поручения сохраняет узнаваемость входного формата для внешних участников, не протаскивая имя «PRD» внутрь пайплайна.
- Периодический HITL и статус — практический предохранитель против бесконтрольного автопрогона (согласуется с уроком про продуктовое вето).

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
| --- | --- |
| Несколько Поручений на входе (fan-in) | Сложно для понимания/контроля/реализации; один-в-один проще |
| Хранить состояние в контексте субагента | Не переживает выключение; источник истины — рабочая директория |
| «Происхождение» = только непосредственный родитель | Труднее искать предков; выбран денормализованный список |
| Не использовать имя «PRD» на входе | PRD узнаваем и понятен внешнему Пользователю; отклонено только имя *внутри* пайплайна |
| Фиксировать Cursor-специфику (пути `.cursor/…`) | По решению экспериментатора не пишем; достаточно нейтральных Skill/Agent/Command |
